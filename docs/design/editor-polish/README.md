# Editor polish — the cheap keymap and attribute wins

Evidence for three items from `1-projects/context-lc-editor-polish/ux-sweep.md`:
K1 (Tab indents a list), P1 (spellcheck is on) and R3 (a fenced code block is
highlighted by its own language). All three are decorations or bindings on the
same CodeMirror configuration `apps/mobile/features/console/files/editorSetup.ts`
and `livePreview.ts` already ship — none of them needed a product decision.

`shots/editing.png` is `LiveEditor.web.tsx` at 390×844 (a phone's width),
rendering a fixed note with a heading, a two-item list and a `js` fence. It
shows R3: `const` in the link colour, `// running total` in the muted colour,
italic. K1 and P1 are asserted in `editing.html`'s own generator
(`scripts/editor-polish-shots.ts`) rather than shown, because neither
produces a picture worth looking at — Tab's effect is two spaces nobody can
see in a screenshot, and spellcheck squiggles depend on a dictionary a headless
browser does not load.

Generated by:

```sh
cd apps/mobile
pnpm exec jest --testMatch '**/scripts/editor-polish-shots.ts' --testPathIgnorePatterns '[]'
```

Then photographed with Playwright at 390×844. `editing.html` is
self-contained — react-native-web's atomic stylesheet, CodeMirror's base
theme and the live-preview rules are all inlined — and holds no customer
content, only the fixed demo note above.
