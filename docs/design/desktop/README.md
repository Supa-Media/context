# The shell title band

Evidence for `docs/decisions/desktop.md`, "The console reserves the space, the
shell places the buttons" — the defect the owner saw on the installed app:
`createConsoleWindow`'s `titleBarStyle: "hiddenInset"` keeps the traffic lights
but removes the bar that used to hold them clear of the page, and the hosted
console drew its own chrome from `x: 0` — so the close/minimise/zoom buttons
sat on top of the active-context chip.

The fix, and what these pictures are of: a 38px band (`SHELL_TITLE_BAND_PX`,
`@context/desktop-bridge`), full width, in the console header's own colour,
drawn only inside the desktop shell on macOS — `apps/mobile/features/app/ShellTitleBand.tsx`.
It reserves the row; the shell places the real buttons inside it, in a
separate change to `apps/desktop`.

Generated by `apps/mobile/scripts/shell-band-shots.ts` (the `.html`, checked in
beside this file) and `apps/mobile/scripts/capture-shell-band-shots.mjs` (the
`.png`, under `shots/`) — the same two-step technique
`docs/design/obsidian-parity` uses: real components, rendered by react-dom
exactly as react-native-web renders them for a browser, photographed by
Playwright at a fixed size (1280×800, the task's own size for this change).

| | What it shows |
| --- | --- |
| `shots/console-mac-shell.png` | The console inside a Mac shell. The band sits above the top bar, and the `@seyi` chip is clear of the top-left corner a real shell's traffic lights would occupy. |
| `shots/console-no-shell.png` | The same console with no bridge on the page — an ordinary browser tab. No band; the chip sits flush at `y: 0`, exactly as it always has outside the shell. |
| `shots/sign-in-mac-shell.png` | The sign-in screen inside a Mac shell. The same band, the same height, above a screen that has no session yet — because the shell hosts this page before it hosts the console, and the defect is not specific to one route. |

## The one question these pictures answer

**Does the band appear identically on the sign-in page and the console, and
only inside a Mac shell?** Yes to both: `console-mac-shell.png` and
`sign-in-mac-shell.png` show the same 38px strip in the same colour, and
`console-no-shell.png` — every other host this app runs on — shows none of it.
That is the property the fix is built on: the band is mounted once, in
`app/_layout.tsx`, above every route, rather than added to the console screen
by hand and left for a reviewer to notice was missing from sign-in.
