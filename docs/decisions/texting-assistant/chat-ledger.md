# Each chat with Tex has one ledger, and every view is rebuilt from it (2026-11-02)

_Part of [the texting assistant](../texting-assistant.md). Decided by the owner, 2026-11-02: "I want one JSON file for the structured data, a manifest for the way we're structuring the data, like a v1, v2 … I want everything logged, including tool calls and the responses … just one source of all of this", for every one-to-one chat and every group chat, kept in a Durable Object, with what Tex reads, the daily pages and the rest rebuilt from it "on the fly"._

## What holds

- **One ledger per chat.** A person's one-to-one chat with Tex (chat `texts`, whichever line they text on) is kept in their Tex, `person:<workspaceId>`, in their personal workspace's object since 2026-11-02; a group chat's in its own, `chat:<groupKey>` (`texStore/ledger.js`). One row per entry, appended and never edited, so adding a line never rewrites the file; read back, a chat's rows are one JSON document with its manifest first: `{manifest: {schema: "tex-ledger", version: 1, chat, created, updated, count, bytes}, entries}`.
- **Versioned.** Every entry carries `v`; the manifest names the schema and version. A reader that meets a version newer than it knows reads none of it rather than misreading it. A change of shape is a new version, never a silent change of v1.
- **Everything is kept** (`agent/ledger.js`): what they sent and what Tex sent (`text`), its thinking in words (`thinking`), what it said between tools (`said`), each tool call with its arguments, outcome, time and result (`tool`), the answer (`reply`), the advisor's asks (`advisor`), the Mail checker's verdicts (`mail_check`), jobs (`job`) and anything else worth keeping (`note`). A later fact about an earlier entry (a held email settled) is a new entry naming it in `ref`, never a rewrite.
- **One exception, by the owner's rule.** A call that read from another workspace (a `context` other than the one the chat's turns run in) keeps what it asked for, its arguments and how it went, never what came back (`withheld: "other_workspace"`). A person keeps what they learned from work they lose access to; they do not keep a copy of the other workspace's notes.
- **Never a secret.** An argument named like a secret is kept `[hidden]`; saved logins never reach a turn at all ([vault](./vault.md)). A very long result or text is kept cut with its full length in `cut`.
- **Idempotent.** An entry's id is kept once per chat; a retried write adds nothing. A chat event keeps the event's own id.
- **A turn reads the whole chat** (`agent/ledgerHistory.js`). The texting Worker still hands a turn the last day; everything before it is read from the ledger, slim (tool names, never arguments or results), newest first within the log's character budget, and each of Tex's answers is followed by the tools it used. Before this a texted turn saw one day. When the Worker does not hand the day, the turn takes it from the same ledger read (`dayFromLedger`: the Worker's own events by their ids, checked again as the log checks them), never the bucket's event log; a ledger that misses a text the turn covers is counted as `tex_turn_day_missed` and the turn is answered as today's, from the question it was sent (tests: `apps/mcp/test/chatLedgerReads.test.mjs`).
- **Trust is the turn's own (2026-11-05).** The gateway's `reply` entry still says whether its turn read from outside (`clean`), but no later turn is judged by it: every earlier answer is shown as it was said, one to one as in a group ([turn-trust](./turn-trust.md)). Until then an answer whose turn had no clean reply was held back, and every turn shown one was marked in turn, so one email marked the whole chat.
- **One history file, never a folder of days** (the owner, 2026-11-02 08:04: "that ledger … be like a history file … multiple views that you can filter by … a view for what Tex sees"). The Tex page reads it through `POST /tex/page/ledger` (`apps/mcp/src/http/texPage/ledger.js`): `view: "raw"` is the entries as kept, filtered by kind and by day; `view: "sees"` is the chat as the next texted turn is shown it, rendered by the turn's own code, with the settings that shaped it (thinking left out, tool names in, results out, every answer in its words). The page shows it as the chat's **History** (under Behind the scenes, `?view=history`; `apps/mobile/features/tex/page/TexHistoryPage.tsx`): one line a message, time, who and words, left-aligned (the owner approved the artboard on 2026-11-02 after trying bubbles and a right-for-you layout: "go back to the ltr, 1 line slack style"), grouped by day, the newest day first and each day in the order it happened; one row of filters, a day menu (Today, Yesterday, All days, Pick a day) and Texts, Tool calls, Thinking and Background, thinking off until asked for, every filter asked of the gateway; each line opening to its entry as kept (`apps/mobile/features/tex/history/`). Background was "Notes" until the owner asked "what is a note?" (2026-11-02): it is what happened outside a text, and each of its lines says which (routine, answered in another app, advisor, mail checker, job). Two or more tool calls in a row are one line (`3 tool calls · browse ×2, vault_list · 1 failed`) that opens to them (the owner, 2026-11-02: "the tool calls should be collapsed somehow"). In a group each text is named by who sent it, with a reply's quoted message and a picture said in words; a reaction sits under the text it is on (`👍 Mom, Ada`), as in the approved mock, found by the words it quotes or, for an answered tapback that quotes none, as the newest text before it from someone else; one whose text isn't in view stays a line. Opened from the file tree it gets the page's scroller (a history file is a file but has no editor's scroller), and it is read once per chat and filter, not again each time the console's data refreshes (the owner, 2026-11-02: "the page randomly refreshes every 20 or so seconds"). Texts are the `text` entries only: `reply` holds the same words and is not shown twice. "What Tex sees" is its own page under Behind the scenes (`?view=sees`), with those settings and the rendered text; the History page has no view menu over its lines (the owner, 2026-11-02: the dropdown was "not how the mock looked"). It reads the gateway every time and keeps no copy (tests: `apps/mobile/__tests__/texHistoryPage.test.ts`, `texHistoryLines.test.ts`).
- **Opening the history file is opening that view.** `tex/history.ledger.json` (and a group home's) opens in the app as the chat's history, never as JSON in the editor, and nothing reads it as a note (`useOpenNote`, `HistoryFileView`): read through the viewer's own Tex page routes, so the person's own file is their chat, a home's file is the group whose home it is among the viewer's own chats (the picker names each home, `pickerOf`), and anyone else's opens nothing. It reads as a chat (Dev, 2026-11-03, from the artboard he approved): the file is called **History** wherever its name is shown (`displayName`), drawn with an arrow turning back around a clock (`tex_history`, emoji twin 📜); it opens scrolled to the newest line, oldest day at the top, "Show older" above them keeping the line in view; one thin row of title and whose, then the filters (plain words, the off ones struck through), stays above its own scroller; scrolled up, a "Latest" button goes back down; it stays live: every append to the ledger pushes `behind` to an open page (`sectionsForKinds`), and the view reads its newest page again, or on a 30-second timer while the socket is down (Dev, 2026-11-03: "are we making sure we are opening a websocket") (`HistoryFileLines`, `useHistoryRead`, tests: `apps/mobile/__tests__/texHistoryLines.test.ts`). The Tex page keeps newest day first.
- **The old chat is copied in once.** `agent/ledgerBackfill.js` puts the bucket's event log (a group's from its own prefix in its workspace's store; a group has no history record) and, for a person, the history record's older exchanges before what the ledger holds (`prepend`, seqs counting down), a part at a time after a Worker's event post, newest first, until a `backfilledv1` entry sits first. A group's old log is found by the chat the Worker named in its events (its line's group id), never the group key its ledger is kept under, which hashes the id with the line; until 2026-11-02 it was looked for under the key, found nothing and marked every group done, so a group is done only under its own `backfilledv2` mark and its old log goes in before the first one (`apps/mcp/test/chatLedgerBackfill.test.mjs`). An old answer is proven clean only where the history record (the gateway's own) holds it untainted.
- **It leaves with the person.** Download as folders writes the one-to-one chat's ledger as one file, `.context/tex/ledger/texts.json`, `{manifest, entries}` (`apps/convex/functions/texLedgerExport.ts`, owner only); a ledger that could not be read to the end is said to be missing, never left out unsaid. A group's ledger is its people's, sealed as its home is ([chat-homes](./chat-homes.md)), so it rides each of its people's own exports, `.context/tex/ledger/groups/<key>.json` beside theirs: only from their personal workspace, only while they are one of the chat's people (`textGroups.homeUsers`, the Tex page's rule), checked on every page; never a shared workspace's export, and never an owner's who is not in the chat (tests: `apps/convex/__tests__/texLedgerExport.test.ts`).
- **Views, not copies.** What a turn is shown, the daily transcript page, the Tex page's thinking, advisor and mail-check lists, dreaming and export are rendered from the ledger, choosing which kinds to include. Leaving thinking or tools out of what the model reads is a change to a view, never to what is kept.

- **The day's answers are judged by the same replies (2026-11-04).** The answers among the texts a turn covers used to have their turn records (`.context/agent/turns/`) read one at a time: 419 ms of a cold text on 2026-11-03. A turn the ledger holds a `reply` entry for is now judged by it (`loggedTurn.js` `cleanByReply`), clean only if every reply for that turn says `clean`, as a record only ever moves toward not clean; one tainted reply ends the check with no read at all. A turn with no reply entry has its record read as before. A group's turn is unchanged. Retired 2026-11-05 with the rest of the spreading ([turn-trust](./turn-trust.md)): no turn record is read to show a turn its chat.

## This reverses

- "Never a tool's result" in the history and transcripts ([history](./history.md), 2026-10-09; [transcripts](./transcripts.md), 2026-10-15). The grant reason for it now applies only to results from another workspace, which stay out.
- Several copies of one chat (the event log in the bucket and the texting Worker's day of it, the history record, the transcripts, the Tex page's own records). They are folded into the ledger and then retired, one at a time, each after its readers read the ledger.

- **A job's work, the advisor's thinking and the Mail checker's answer are in the chat's one history** (the owner, 2026-11-02, on a decision card: "In the chat's history, tagged"; and "'Its private reasoning isn't kept.' - why?"). A job's turn writes into its chat's ledger like any turn, and every entry it writes carries `jobId` and `jobTitle` (`agent/ledger.js` `jobTagged`, wrapped once in `route.js` so its steps, answer and check all go through it). `POST /tex/page/ledger` takes `job` (that job's work and its own `job` entries) or `jobs: false` (none of any job's work), read in the object by `json_extract` (`texStore/ledger.js`). The History view always reads a job's work and folds it under one line a job where it began (Dev, 2026-11-03: "why can't i see the background jobs thinking and actions", then the Jobs artboard approved with "label it as Tex · Minion 1/2/3"): who is `Tex · Minion N`, numbered in the order the day's jobs began, beside its state from its newest `job` entry, its tries (the turns it took) and its steps; its thinking, calls and checks open under it, a failed call in red, open until the job is done; what it texted the person stays in the chat from `Tex · Minion N` (`historyLines.ts` `foldJobs`). There is no Jobs filter. A job's page shows "What it did", its own lines only. The advisor is asked for its thinking in words (`display: "summarized"`) and it is kept beside its answer, on the `ask_advisor` tool entry and on a job check's `advisor` entry, shown with Thinking on; it never reaches Tex or the texting Worker (`jobChecked` takes it off the fields). The Mail checker's whole answer is kept on its `mail_check` entry as `answer` (tests: `apps/mcp/test/ledgerJobsAndThinking.test.mjs`, `apps/mobile/__tests__/texHistoryPage.test.ts`, `texPageRender.test.ts`).

## Retiring the old copies (the owner, 2026-11-02)

One at a time, each in three steps: its last readers move to the ledger, its writes stop, then it is deleted, its objects kept for a week in the workspace's backup bucket first. Where each stands:

1. **The bucket's event log** (`.context/agent/log/<chat>/`). **Writes stopped:** `POST /agent/events` checks the events at the door (`log.js` `checkEvents`) and appends them to the chat's ledger alone, awaited, so a refused write answers an error and the Worker keeps the events and posts them again (`apps/mcp/test/agentTextingRoutes.test.mjs`). A chat with no ledger (a group grant that names no chat) is still written to the log and counted as `tex_events_to_log`, never into the person's own one-to-one ledger. Its last reader is the copy-in (`ledgerBackfill.js`), which needs only what is already there. A chat that has not texted since is copied in by the `Tex chats into their ledger` workflow (`apps/convex/functions/texLedgerBackfill.ts`, personal workspaces, part after part until the mark is in, counts only in its public log; `apps/convex/__tests__/texLedgerBackfill.test.ts`). Next: run it, then delete, after a week in the backup bucket.
2. **The texting Worker's day of it** (`apps/agent/src/events.ts`, kept for decide and handed to a turn as `recent`). **Retired** (Dev, 2026-11-02: "Outbox only, read the ledger"): the Worker keeps only the events the gateway has not taken, forgetting each once `/agent/events` answers it, and drops what an older version kept on its next flush. Every reader of the chat on the Worker (decide, the group recheck, a reaction on Tex's own text, a progress line said once, the review watch) reads the chat's last day from the ledger through `POST /agent/chat` (`textingRoutes.js` `handleChat`), with the outbox on top (`apps/agent/src/chatRead.ts`), using the token of the last turn that opened the chat, held in memory only. With none (an object that just woke) or no answer within 1.5 s, the reader gets the outbox alone, counted as `tex_chat_read`. A turn is handed only the outbox as `recent`, never `holdsLog`, so the gateway reads the day from the ledger and adds it (`warmCopy.js` `mergeEvents`) (tests: `apps/agent/src/chatRead.test.ts`, `apps/mcp/test/agentTextingRoutes.test.mjs`). The gateway ignores an older Worker's `holdsLog` and hands no log back to hold (`warmCopy.js`; `apps/mcp/test/agentHeldLog.test.mjs`). What a group says while Tex stays quiet is posted as it is said: with the last turn's token when the Worker holds one, otherwise by the chat's ledger key over the `TexTexts` binding (`POST /texts/events`, `textsDecide.js` `eventsForTexts`), checked as `/agent/events` checks them and taken only for a chat that already has a ledger (Dev2's pick, 2026-11-13, after Tex Devs texts reached the ledger hours late once a deploy or an idle hour had dropped the token). Simplifying this back to the token alone makes a quiet group's history stop at Tex's last answer again; `apps/agent/src/chatRead.test.ts` ("chatter with no token in memory") fails.
3. **The history record** (`history.js`). **Readers moved:** every reader of the one-to-one chat (a turn's history and its taint, `earlier_texts`, threads, the sharing judge's words, the check-in, routines, the memory nudge, the self-review, a yes overtaken, the report gate) reads the chat rebuilt from the ledger (`ledgerConversation.js`), and the record only where a store keeps no ledger (counted as `tex_history_from_record`). The rebuild: their texts, each run of them one question; Tex's texts of a turn as its answer, shown only when the gateway's own `reply` entry for that turn exists, tainted unless it says `clean`; a Tex text nobody vouches for is never shown. A check-in, a routine's run or a settled yes is its `note`, with its `tainted`, `thread` and `sources`; a routine texting other people (`others`) is not this chat's. The reply entry carries what the record kept beside an answer: `attached` (the files they sent, where a picture is kept), `sources` and `thread`. A turn the Worker logged no texts for (it named none it covers) has its two texts written by the gateway (`exchangeEntries`), and a fixed text the Worker sent is written by the gateway before the turn reads, beside the Worker's own copy, the two shown once (`appendTold`). Any caller that keeps the person's texts writes the ledger, not only the texting Worker. **Writes stopped** for a chat whose past is copied in (its `backfilledv1` mark sits first, `ledgerConversation.js` `copiedIn`): from then on no turn, check-in, routine or fixed text writes the record, and a person who joins after this never has one (`apps/mcp/test/texHistoryOneCopy.test.mjs`). A chat not yet copied in goes on writing it, so its fallback stays whole. The desk's note keys (`direct`, which About me, the jobs list and the voice note are read by) are kept by themselves in `.context/agent/history/desk.json`, an older record's own read until those are written (`texStore/desk.js`). **Retired** (2026-11-09, a week after every chat was copied in: sweep 27 already, 0 would): nothing reads or writes the record any more. `readConversation` reads the ledger alone, marked or not, and a store with no ledger has no conversation (every store that could reach the record reaches the ledger too: both are the person's object); `appendConversation` writes only the ledger's note, and the reply path no longer calls it (`apps/mcp/test/agentConversation.test.mjs`, `ledgerConversation.test.mjs`). The tests that played the texting Worker without posting its texts now post them (`agentEgressFixtures.mjs` `textTex`, the bench's `world.text`). Next: delete the records themselves.
4. **The daily transcript pages** (`transcript.js`). **Writes stopped:** no turn writes one. The dream and the hand-back miner read the person's ledger instead (`ledgerDays.js`), and texted pictures are kept in `tex/pictures/` ([transcripts](./transcripts.md)). The old pages are a second copy of the chat, so once a person's chat is whole in its ledger their `tex/transcripts/` folder is moved to the trash, restorable for 30 days (Dev, 2026-11-02: "Why do we still have duplicated information?"; `apps/convex/functions/texTranscriptsTrash.ts`, workflow "Tex chats into their ledger", scope `transcripts`).
5. **The Tex page's own records**. Not started.
6. **A group chat's memory page** (`tex/groups/<words>/history.md`, "Tex's memory of this group chat", `groupMemoryNote.js`). **Retired** (Dev, 2026-11-02, on a decision card: "Retire it, one copy"): it was the copy every group turn read and added to, beside the ledger that holds the same texts. A group's turn copies its page into the chat's ledger once, before everything there and only after the chat's old log is in (`GROUP_BACKFILLED` first), stopping at the first of Tex's answers the ledger already holds, each entry's id a hash of what it holds so a copy run twice keeps one; a `pagecopiedv1` mark then goes first (`groupPageCopy.js`). From then on the turn reads its history rebuilt from the ledger, each run of texts one question with what people said to each other in the block the Mail checker strips and the text that tagged Tex after it, each named (`groupQuestion`); no turn reads or writes the page, and the prompt names the history, not the page (`groupTurn.js`). The quiet groups are copied in by the `Tex chats into their ledger` workflow (scope `group_pages`, `apps/convex/functions/texGroupPagesRetire.ts`), which also makes each home's `history.ledger.json` (made before only on the chat's next text) and moves the page to the trash, restorable for 30 days, only once the ledger carries the mark, read again just before (tests: `apps/mcp/test/groupPageCopy.test.mjs`). A chat Tex has never answered (no record) whose home holds no page starts on its ledger: its first turn writes the `pagecopiedv1` mark with nothing before it, so no page is ever made and its record keeps marks, never turns (`startOnLedger` in `groupTurn.js`). Until 2026-11-12 a new group still made `history.md` on its first text and copied it in on its second, and nothing trashed it, so its home showed two history files (Nov Babies; Dev2 chose "Stop it and clean up"). The leftovers are trashed by the same workflow scope.

## What a simplification would cost

- Keeping a second store "for the page" or "for speed": two records that disagree, the regression the owner rejected repeatedly ([one-to-one-history](./one-to-one-history.md)).
- Keeping another workspace's results: a chat holding notes its people may no longer reach.
- Rewriting the whole file on each append: every text would grow slower with the chat's age.
