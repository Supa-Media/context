# The Architecture Lab is a staff page, built exactly like its artifact (2026-11-13)

Dev2 designed the Tex Architecture Lab as an artifact on 2026-11-13: change
Tex's steps, wires, each step's model and context modules on a canvas, see
what that does to reply time and cost, edit the bench's test cases, and hand
the version to the replay gate. The same day Dev2 asked for it to be built for
real, "EXACTLY like the artifact with all the functionality wired up".

**Where:** context.lc/lab and tex.lc/lab (`apps/mobile/app/(app)/lab.tsx`;
Dev2, 2026-11-13), reached like the staff console, by typing the address;
`/admin/lab`, where it first opened, redirects there. Staff only on
the server: `apps/convex/functions/texLab.ts`, `requireAdmin` in every
handler. Saved versions and case edits are two tables every staff member
shares (`texLabVersions`, `texLabCaseEdits`); they hold the Lab's own JSON
(graphs of steps and wires, edits to the bench's public cases), never a note
or anyone's chat.

**The artifact is the spec.** The stylesheet is its `<style>` scoped under
`.tl` (`features/tex/lab/labCss.ts`), the shell is its markup with the same
ids and classes, the constants are copied verbatim (`features/tex/lab/data/`),
and the engine keeps its function names and its one state
(`features/tex/lab/engine/`). `__tests__/texLabEngine.test.ts` holds the port
to the numbers the artifact's own page computed. A view that looks or acts
differently from the artifact is a bug, unless it is one of the stated
differences below. `node scripts/tex-lab-preview.mjs` builds the page with
Convex stood in, so the two can be screenshot side by side.

**Stated differences:** saving goes to Convex rather than the artifact's page
database ("Shared · n saved versions"), and the Tools page also reads live
tool figures.

**Main's graph is what main runs** (Dev2, 2026-11-13: "how accurate is the current lab graph?"). The artifact's
graph had the fallback off and five efforts wrong (jobs at high; the reviewer, mail checker, hand-back judge and
self-review at medium) and no send-back from the answer checks. Main's graph now follows the code and the
production setup as the fingerprint gate keeps it, and `__tests__/texLabMainGraph.test.ts` fails when either moves
without it. The port's golden tests still run on the artifact's own graph (`fixtures/texLabArtifactGraph.json`).
Times are the model table's estimates, not measurements.

**The Lab's config is Tex's one config** (Dev2, 2026-11-13: "I want the config generated by the lab to become the
production code, and to be the only source of truth"). `packages/shared/src/texConfig.json` holds every step (its
model, effort, on or off, time limit, rounds, and the context it reads in order) and every wire, in the Lab's own
graph shape; main's graph in the Lab is that file, read as it is. The move happens in five pull requests, each live
before the next: the file and the Lab reading it; the gateway reading models, efforts, on or off and time limits from
it, with the per-file constants and the setup note's model lines deleted; prompt modules and their order; a
`tex.md` steps table generated from it; and the Lab's Promote opening the pull request that changes it, gated by the
replay gate like any Tex change. The wires are the file's too: since 2026-11-14 one runner reads them and the nodes are
code ([config-graph](./config-graph.md)), so a new step from the Lab ships as the file and its node's code together. `docs/architecture/tex.md` carries the file's steps table, generated by `scripts/tex-config-table.mjs` and kept
out of the prompt's copy of the page; `tex-diagram-check.mjs` fails when the table is stale or a drawn box names
another model or effort than the file.

**Promote** (the button beside Save) records an ask (`apps/convex/functions/texLabPromote.ts`); the Tex Lab promote
workflow (`.github/workflows/tex-lab-promote.yml`, every quarter hour) writes the version's graph into the config
with `scripts/tex-lab-promote.mjs` on a branch of its own and opens the pull request, which merges like any Tex
change. It refuses a new step (its code comes first, on a branch), a deleted one (turn it off), a model with no
gateway id, and new words for a module built in code. Production's setup note names no models;
AI Promote refuses a texting setup that names its own (`bench/promote.mjs` `configRefusal`).

**Tex's prompt words live in the repository, beside the config** (Dev2, 2026-11-14, choosing "In the repo, beside
the config" over keeping them in `@context-lc` pinned by fingerprint: a pinned copy is a second copy that can only
fail). Each module is `packages/shared/src/texPrompt/<name>.md`, the words exactly as Tex is given them;
`scripts/tex-prompt-module.mjs` writes them into `texPrompt.generated.json`, which the gateway and the Lab import, and
`tex-diagram-check.mjs` and `texConfig.test.mjs` fail when it is stale. Which modules a turn gets, in order, is the
config's: the `p-<name>` entries of the front door's context for a 1:1 text and a group, and of the background
job's for a job (`texConfig.js` `texModules`). A texting setup that names neither models nor modules, as
production's does, is given them (`production.js`); a bench variant naming its own keeps them, a live read says so
(`tex_setup_not_from_config`, with the modules whose words differ from the repository's), and AI Promote refuses one.
The Lab shows the repository's words, and Promote writes a version's new words for a `p-` module into its file in the
same pull request as the config, so a word change is a prompt change the fingerprints see and the replay gate runs.
The `ai/production/prompt/` notes are retired. Skills stay in `@context-lc` for now.

**Its data is the bench's own.** `scripts/tex-lab-data.mjs` writes the cases,
the module texts (the map, the capability list, the judge examples, the test
person's about note) and the test workspaces from the repo into
`labData.generated.ts`. Fast repository guards fails when that file is stale.

**What a simplification would cost:** rebuilding the views "in the app's own
style" instead of porting them would bring back the thing Dev2 named, a build
that isn't what was designed; keeping versions in browser storage would lose
the comparison between staff members' versions, which is half the point.

## Replaying a person's own texts (Dev2, 2026-11-13)

Dev2's ask: "give me the ability to change the user to my user, and
essentially replay old messages, this means that we have to log which version
of tex a message is going through in the history ledger, it also should
probably be read only".

- **Every turn names its Tex.** The turn's `reply` entry in the chat ledger
  keeps `version`: the deployed commit (`TEX_CODE_VERSION`, passed by the
  deploy workflows), Cloudflare's Worker version id (`CF_VERSION_METADATA`)
  and the live setup's version (`production.js` `versionOf`), because the
  words Tex runs on change in Context, outside a pull request
  (`apps/mcp/src/agent/texVersion.js`). A turn's own reads drop it, so it
  changes no prompt.
- **"You" is the signed-in staff member, and only their own 1:1 chat.** The
  Test user swap in the Lab's sidebar reads their texts through the Tex page's
  history route, which answers only a person's own chat. No chat carries a
  consent flag, so nobody else's chat is replayed; group chats are left out
  until one does.
- **Read only by construction.** A picked text goes into the run config
  (`replays`, `replayAs`). The session fetches the notes that turn read through
  its own Context connection, and `pnpm ai lab replay`
  (`apps/mcp/bench/labReplay.mjs`) runs each text in the bench's throwaway
  world: in-memory buckets, a stub control plane, no Sendblue, no mail. It
  refuses a notes or scratch folder inside the repository, which is public.
- **The words stay in the tab.** A pasted "## Lab replay" shows Then beside
  Now under Your texts, and is never saved with the version, which every staff
  member reads.

**What a simplification would cost:** replaying through the production
gateway would let a replay text somebody or change a note; saving the replay
with the version would copy one person's chat to every staff member; dropping
the version stamp would leave Then with no way to say what produced it.

`apps/mcp/bench/test/labReplay.test.mjs`,
`apps/mobile/__tests__/texLabMine.test.ts`,
`apps/mobile/__tests__/texLabMineView.test.ts`.
